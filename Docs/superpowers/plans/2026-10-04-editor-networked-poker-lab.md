# Editor Networked Poker Lab Implementation Plan

> **For agentic workers:** Execute tasks in this session, task by task, preserving the existing dirty Unity upgrade and debug changes.

**Goal:** Build a playable Unity Editor heads-up poker table that connects to the local Node server and plays against a server-controlled Bot.

**Architecture:** The Unity lab explicitly creates a `LOCAL_BOT` room, starts the hand after the Bot is seated, submits HUD and chip gestures through the existing semantic action path, and renders authoritative snapshots. The server adds a Bot only to explicitly requested local rooms and schedules its legal actions through `PokerEngine`.

**Tech Stack:** Unity 6.3, C#, Unity UI/TMP, Node.js, TypeScript, `ws`, existing smoke-test scripts.

---

## Task 1: Add Explicit Local Bot Rooms

1. Add `opponentMode?: "LOCAL_BOT"` to `CreateRoomMessage`.
2. Keep the default room path unchanged when `opponentMode` is absent.
3. Add an internal Bot player in seat 1 only for `LOCAL_BOT` rooms; identify it with stable ID `local-bot` and display name `Dealer Bot`.
4. Keep a Bot-ID set in `PokerRoom`; public presence reports Bot players as connected, and hand-start eligibility includes the Bot even though it has no socket.
5. Confirm ordinary rooms still require two connected human players.

## Task 2: Schedule Authoritative Bot Actions

1. Add one cancellable action timer to `PokerRoom`.
2. After a hand starts and after each accepted action, schedule the Bot only if the room is in a live street and the current action seat belongs to the Bot.
3. On timer fire, read `PokerEngine.legalActions(botId)`, select the agreed conservative legal action, and call `PokerEngine.apply`.
4. On an accepted Bot action, increment the room version and broadcast the ordinary snapshots; if the hand settles, publish settlement and schedule a new hand after the result pause when both players still have chips.
5. Prevent duplicate timers and stale callbacks by checking the hand ID, room version, current actor, and timer ownership before applying.

## Task 3: Verify the Server Bot Flow

1. Add `botSmoke.ts` with fake open WebSocket peers that capture server messages.
2. Create a local Bot room, assert the public snapshot contains two seats and never exposes the Bot's private hole cards to the human.
3. Start a hand and assert the Bot acts only after the human action makes it the current actor.
4. Assert the Bot action increments versions, changes the authoritative state, and returns the turn to the human or advances the street.
5. Run `npm run typecheck` and `npm run smoke` from `Server`.

## Task 4: Add Unity Local Room Lifecycle

1. Add a `CreateLocalBotRoom()` session method that emits `opponentMode: "LOCAL_BOT"`.
2. Add room-created and connection lifecycle events to `PokerSessionClient` so the lab bootstrap does not infer room creation from unrelated snapshots.
3. Implement `LocalPokerLabBootstrap` to bind the synchronizer and action client before connecting, request a room once, then start once after two players and a null hand ID are observed.
4. Make startup idempotent and render errors/disconnects through a public status event.
5. Keep the bootstrap free of poker rules and snapshot mutation.

## Task 5: Complete Snapshot Presentation and HUD

1. Render public board cards into five fixed slots and clear unused slots.
2. Render opponent card backs from the opponent's `holeCardCount`; never pass opponent card values to view components.
3. Add status, street, current actor, and room code labels.
4. Add a bet/raise amount control bounded by `LegalActionGate.MinRaiseTo` and `MaxRaiseTo`.
5. Wire fold, check, call, bet/raise, and all-in buttons through `PokerActionBridge`; disable actions when the server snapshot does not permit them or the transport is disconnected.

## Task 6: Generate and Save the Lab Scene

1. Add an Editor-only menu command that creates the scene hierarchy, tabletop and card/chip primitives, Canvas, seat labels, community-card slots, local private-card views, opponent backs, legal-action HUD, bet controls, status labels, and the required networking/interaction components.
2. Assign all component references explicitly in the builder, including the transport, synchronizer, session, action client, gate, normalizer, sink, bridge, mouse provider, resolver, betting zone, and presentation binders.
3. Add the local lab scene to `EditorBuildSettings` using the Editor API.
4. Run the menu command in the already-open Unity Editor to save `Assets/Scenes/PokerInteractionLab.unity`.
5. Open the saved scene and verify entering Play Mode connects to the running server and displays a dealt hand.

## Task 7: Document and Hand Off

1. Document `npm start` followed by opening `PokerInteractionLab` and pressing Play.
2. Document that the mouse controls a pinch, chip stacks can be dragged to the betting zone, and the HUD is the fallback action path.
3. Run server checks and Unity Editor Play Mode validation.
4. Inspect `git diff --check`, review generated Unity files, and report every authored and generated change separately.
